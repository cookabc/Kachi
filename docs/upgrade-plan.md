# Kachi 升级优化方案

> 基于 2026-10-26 的实测（430×932 视口、真实课程数据、150 测试全绿）。所有数字都量过，不是印象。
> 结论先行：**工程质量不是瓶颈，内容可信度、学习成果可见性、题目卡空间利用率是。**

## 阶段 P0 · 修死路与达标（半天，不动设计）

### P0-1 让「验证掌握」真正可达 ✅ 已完成（2026-10-27）

**修法**：新增 `isFirstEncounter()`，用 attempts 日志里该 exerciseId 的首现判断，
取代从未被赋值的 `assessmentOnly`。只对 lesson 模式生效——练习课是有意重复已学内容，
把它算成「首次遇到未见场景」会让判据自欺。新增 4 条测试（src/mastery.test.ts），
其中一条真的把 unit 1 三课全打对，断言 verified mastery 确实成立。

原链条：

```
applyAnswer → isUnseenScenario = exercise.assessmentOnly && type === 'scenario'
            → unseenScenarioCorrect ||= isUnseenScenario
isVerifiedMastery = consecutiveCorrect >= 3 && evidenceTypes >= 2 && unseenScenarioCorrect
```

而内容里 `assessmentOnly` 是 **0/51**，所以整条链恒假。两条修法，推荐第二条：

- **（不推荐）** 给 51 道 scenario 手工标 `assessmentOnly`。语义上不对：它们本来就是课程内的题，不是"未见过的场景"。
- **（推荐）** 改判据为「该题在本次作答前从未出现过」，即用 `attempts` 日志里该 `exerciseId` 的首现判断。这不需要动内容，且语义更准：真正的"未见场景"就是第一次遇到。

配套：`docs/` 里写清「掌握」的定义（连续 3 次正确 + 至少 2 种题型 + 通过一次未见场景），因为这是产品承诺，必须可核对。

### P0-2 掌握状态要能看见 ✅ 已完成（2026-10-27）

引擎已经在算 `consecutiveCorrect` / `lapses` / `evidenceTypes` / `unseenScenarioCorrect`，UI 一个都没用。图谱目前只有 `seen | unseen | missed` 三态。

改成四态（复用现有数据结构，不新增字段）：

| 状态 | 判据                     | 视觉      |
| ---- | ------------------------ | --------- |
| 未学 | 不在 `seenConceptIds`    | 空心圆    |
| 见过 | 已 seen，无 mastery 记录 | 实心浅色  |
| 在练 | `consecutiveCorrect` 1–2 | 半环      |
| 掌握 | `isVerifiedMastery()`    | 满环 + 勾 |

这条同时是差异化：词光用「点亮一颗星」把进度做成可炫耀的，Kachi 的弦图比星图信息密度高得多，只是没把掌握度画上去。

**实施时改了一处设计**：原计划靠填充色区分四态，实测 CIELAB ΔE 发现
「已学」与「已掌握」的填充色完全相同（ΔE=0），「未学」与「在练」只差 11.1。
单纯换颜色解决不了，因为两者本来就该是同一族绿色。所以改成**几何区分**：
未学=细边空心、已学=实心、在练=粗边空心、已掌握=实心+外环光晕。
形状在任何色板与任何色觉下都成立。

### P0-3 清数据与达标

- 幽灵 `termId`：`sell`、`put_u1intro` 不在 concepts 表。`sell` 作为选项 art 是合法的（干扰项），作为 `termIds` 不是——它会进 `attempt.conceptIds` 再被 filter 掉，属于脏数据。`put_u1intro` 是引言语境的临时 id，应删或正式收编。
- 未选中导航 `rgb(139,141,152)` 在 13px 下 4.01:1，改到 ≥4.5。
- CSS：5 个未使用变量（`--green-2`/`--locked`/`--yellow-deep`/`--violet`/`--radius`）、`--t-fast` 与 `--t-med` 同值 250ms（应删一个）、10 处 `!important`、34 个重复选择器块（`.g-card`×3、`.nav`×2…）。

### P0-4 计分语义定案

重试题（`requeuePrompt`）目前**既计入分母、又更新 mastery**。两种后果：

- 一次错答会让正确率上限永久压在 10/11≈91%（分母被重试撑大）；
- 重试答对会推进 `consecutiveCorrect`——等于"错了还能靠重试攒连对"。

建议采用与词光一致的规则：**一轮里只有首次作答更新记忆，重试只作练习不评分、不进分母**。改动集中在 `applyAnswer` 加一个 `isRetry` 标记。

---

### 「掌握」的判定标准（产品承诺，可核对）

一个混淆对被判定为「已掌握」，需要同时满足三条：

| 条件 | 字段 | 为什么 |
|---|---|---|
| 连续答对 3 次 | `consecutiveCorrect >= 3` | 单次答对可能是蒙的 |
| 至少用过 2 种题型 | `evidenceTypes.length >= 2` | 只会做选择题不等于会用这个词 |
| 在真实场景里答对过 | `unseenScenarioCorrect` | 见过定义的词，第一次在句子里遇到仍可能认不出 |

「未见场景」= 该题在作答前从未出现在你的 attempt 日志里，且是课程模式下的首次作答。
这个定义写在引擎里（`isFirstEncounter`），由 4 条测试守着，不是文档约定。

## 阶段 P1 · 内容可信度（2–3 天，这是立身之本）

### P1-1 补齐溯源

`sources` 表里已有 4 条一手来源（FINRA/SEC SBLOC、IRS Topic 409 等），但只被 3 个概念引用。40 个概念里 37 个 `sourceIds: []`，26 个 `reviewStatus: "legacy"`。

schema 机制是齐备的（`sourceIds` / `risk` / `reviewStatus` / `rightsBasis`），**缺的是内容**。做法：

1. 每个概念至少挂 1 条 `kind: "primary"` 来源；确实没有权威来源的（如 `buy-borrow-die` 这类行业说法），`risk` 标 `jurisdictional` 并在 `note` 里写明"这是流行说法而非监管定义"。
2. 定一个 `legacy → reviewed` 的可检验标准（谁复核、核什么、留什么记录），写进 `docs/content-review.md`。
3. `scripts/validate-content.mjs` 加一条硬校验：`reviewStatus: "reviewed"` 的概念必须有非空 `sourceIds`。让内容规范变成构建门禁，而不是文档里的自觉。

### P1-2 题库均衡

> **已被 [vocabulary-system.md](vocabulary-system.md) 取代。** 在现有 40 词内部调密度解决不了
> 「词汇域偏了」的问题——实测这 40 词在 172 条真实标题里只命中 25%。词库已按语料重做为
> 6 层 231 个词条。题库均衡应放在 pack 边界确定之后再做。

实测每概念被考次数：`hedge` 15、`pledge` 14、`short selling` 11、`margin call` 10、`leverage` 10；中位 6；`sell` 和 `put_u1intro` 只 1 次。

u1 每课 10 题，u3–u7 每课 8–9 题。前两个单元承载了整个产品的示例重量，后五单元（利率、曲线、基差这些更难的）密度反而低。

两条路，选一条并写进文档：

- 补齐到 40 概念 × 6 题 ≈ 240 题，后五单元加题；
- 或明确"前两单元是入门铺垫所以更密"，那就在 `docs/` 里说清楚，别让人以为是缺漏。

### P1-3 引入「疑」题型（差异化）

上一轮从 XQuant 的「做 / 看 / 疑」得出的结论：现有五题型（meaning/truefalse/fill/scenario/match）全是**回忆与辨识**，没有"审查一个论断哪里站不住"。

金融英语的真实使用场景就是读研报然后怀疑它。加 `audit` 类：给一段含陷阱的短文本（单位错、区间偷换、幸存者偏差），让学习者揪出问题句。schema 加 `ExerciseType`，`why` 字段承担讲解。这条别人没有，且与 208 题池完全兼容。

## 阶段 P2 · 视觉与空间（2 天）

### P2-1 题目卡不要空着

实测 `.prompt` 卡内部空白：

| 题型    | 卡高  | 内容占 | 空白            |
| ------- | ----- | ------ | --------------- |
| teach   | 764px | 618px  | 146px (19%)     |
| meaning | 764px | 412px  | **352px (46%)** |
| fill    | 764px | 245px  | **519px (68%)** |

根因：`.prompt` 是 `flex: 1`，内容少时被拉伸填满。改法按优先级：

1. **让卡跟内容走**：内容不足时 `align-self: flex-start`，把剩余空间留给反馈区——反馈面板本来就要占位置，空着不如让它更大。
2. **把留白变成内容**：fill 题的 `bank` chip 只有 116px，可放大成主视觉（大号词卡，点击有重量感）；meaning 题的 4 个 tile 从 176×153 放大到 ~200 高，文字从 13px 提到 14px。
3. **teach-art 撑满**：容器 180px 高、SVG 只有 118px（填充率 57%）。让图形占满可用高度。

### P2-2 词汇表折叠

40 张卡 × 361px = 21.6 屏。默认折成一行（术语 + 中文 + 混淆词），点击展开对照台。这是 033 验证过的同一招（会话按文件夹折叠 5514px→1850px）。

折叠后组头必须保留全信息（术语、中文、混淆对象），因为它是唯一可见的东西；`ContrastBench` 的 `split` 状态要跨重绘保留，否则每敲一个字刚拖好的分隔线又复位。

### P2-3 学习路径折叠

23 张卡 = 3.8 屏。按单元折叠，默认展开"当前单元 + 下一课"，其余收成单元条（单元名 + 进度 n/m）。图谱与词汇表已经是按单元分组的，视觉语言一致。

### P2-4 中文标题的字体与字距

`--display` 是 Dela Gothic One，但它的 `unicode-range` 只覆盖拉丁（`U+0000-00FF` 等），中文标题实际回落到 PingFang。而 `.lab-section-head h2` 在 34px 上应用了 `-0.045em` 负字距（实测 -1.53px）——拉丁字体的收紧规则套在中文字上会挤。

建议：中文标题单独一条规则（正字距或 0，字体显式写 PingFang 粗体），让"英文用 Dela、中文用黑体"成为有意的排版而不是回落。

## 阶段 P3 · 产品差异化（1–2 周）

### P3-1 音频（最大的缺口）

语言学习产品没有声音。全仓 0 音频、无 IPA 字段。

量级：40 术语 × 英/美 + 40 条例句 ≈ 120 个文件，估计 2–3MB，PWA 可整包 precache。

路径：
1. 先验 fish.audio 能否稳定出**可区分的英/美双音色**（本机有订阅和实测过的 API 形状），不行退到单音色 + `speechSynthesis` 兜底。
2. 数据形状抄词光：索引行带 **media 位标记**（1 发音 / 2 例句 / 4 图片），前端按位判断有就播、没有就静默——这是为"渐进补资产"设计的，不用一天补齐 120 个文件。
3. 加「听音辨词」题型（词光四题型之一，Kachi 完全没有）。

### P3-2 提示机制

`hintUsed` 引擎已支持（`!correct || hintUsed` → 计 Hard），但 UI 没有入口。加一个「给首字母/给半个定义」的提示按钮，用了就降级为 Hard。这是从"只能对错"到"知道自己在猜"的一步。

### P3-3 错题本

`attempts` 是全量日志（含 `exerciseType` / `correct` / `conceptIds`），目前只在结课屏显示最多 3 个 mix。可以做：

- 按混淆对聚合的历史错误率；
- 一道题"你错过 3 次、最近一次在 5 天前"；
- 导出成可读的复盘清单。

### P3-4 顺带接线 `latencyMs`

现在恒为 0。接上真实计时（`onPick` 时记开始、`submit` 时算差），它是 P3-2 提示阈值和未来自适应难度**唯一**的数据来源。不接的话这个字段应该删掉，别留着假装有数据。

## 明确不做

| 不做                       | 理由                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 深色模式                   | README 已定：墨纸"笔记本"就是品牌，2026-10-04 决策，需真实夜间阅读场景才重议                        |
| FSRS 自适应                | 40 概念量级，固定阶梯 [1,3,7,14,30,60] 与自适应拉不开差距；等扩到多 pack 再换                       |
| 换掉弦图改成星图           | 弦图表达"词与词的混淆关系"，是 Kachi 的差异化；星图只表达掌握度，两者要并存不要替换                 |
| AI 插画替换手绘 SVG        | 40 个术语量级下手绘就是最优解；`art.tsx` 的双色板纪律（场景色板与 chrome token 永不互窜）是品牌本体 |
| 加原生壳                   | Web Push 才是第一个真实后端需求                                                                     |
| 三方向门 / 设计 skill 门禁 | 那套工序是给一次性 HTML 交付用的，日常产品迭代不适用                                                |

## 建议执行顺序

```
P0（半天）  掌握判定可达 → 掌握状态上界面 → 幽灵 id → 导航对比度 → CSS 清理 → 计分语义定案
P1（2-3天） 溯源补齐 + 构建门禁 → **词库重做（见 vocabulary-system.md）** → audit 题型
P2（2天）   题目卡空间 → 词汇表折叠 → 学习路径折叠 → 中文标题排版
P3（1-2周） 音频 → 提示 → 错题本 → latency 接线
```

每一步的验收都用同一套方法：`vitest run` 全绿 + 浏览器实测几何（空白率、屏数、对比度数字），不接受"看起来好多了"。
